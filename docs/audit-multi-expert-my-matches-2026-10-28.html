Synthèse exécutive

Le widget est fonctionnel, compilable et nettement plus raisonnable que la version 5.7 : l'injection shell est corrigée, les ligues sont filtrées, les caches mensuels existent et le live n'appelle plus le réseau sans match. Il reste toutefois un objet dense, difficile à valider, avec des chemins de démarrage à froid et de petite tuile qui ne sont pas couverts par les tests actuels.

Verdict d'usage personnel : GO conditionnel. Le widget peut rester sur l'écran d'accueil pour un usage local. Les conditions sont la surveillance des timeouts de démarrage, l'acceptation du risque sur les petites tailles de tuile et la non-publication des captures telles quelles.
Verdict de publication communautaire : NO-GO en l'état. Il manque une LICENSE effective, une CI reproductible, une validation device de v5.9.8, une stratégie d'accessibilité et une correction des budgets de timeout. Aucun de ces points ne nécessite de retirer une fonctionnalité.

Lectures rapides

  • Fiabilité. Les sources lourdes n'ont pas toutes un budget de timeout compatible avec leur pire cas : scheds, standings, teamsDb.
  • Démarrage. Dix sources cmd peuvent partir ensemble ; les caches chauds masquent un cold start encore coûteux.
  • Rendu. Aucune animation 60 fps, mais des listes non lazy et des tableaux ouverts par défaut. Le coût est à l'ouverture, pas en continu.
  • Énergie. La boucle every 1s réveille le widget en permanence, même sans spinner.
  • Accessibilité. Les logos et de nombreux contrôles n'ont pas de nom accessible ; c'est le principal écart de qualité perçue.
  • Traçabilité. Le distant GitHub est sain, mais la copie locale auditée avait un Git cassé ; la publication de ce rapport répare cette trace.

Contrats de données

Match
id, league, tag, at, state, detail, squads, tids, odds, teams, home, away, stage, round, month. id est unique ; at est un epoch UTC ; state ∈ pre/in/post.
Classement
league, tag, group, ends, teams[{abbr,name,rank,played,won,drawn,lost,bp,bc,gd,pts,ours,zone,zlabel}], legend.
Équipe
key=abbr:kind, name, short, abbr, display, logo, league, tag, kind, tid. Le key est la clé métier stable.
Cache
Signature pour les matchs, lms pour les mois, fusion fraîche + ancienne, validation jq avant écriture.
