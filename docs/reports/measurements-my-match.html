Ce que cela change pour la batterie

Le régime stable est ce qui tourne en permanence quand le téléphone est sur l'accueil. v5.7 exécutait 82,5 curl + 161,5 jq par minute ; v5.8 exécute 0 curl + 4 jq par minute sans match live. C'est la source principale du drainage qui disparaît, et non un simple lissage.

Validation. v5.8 est réinstallé à la fin du script (et par le trap), les wrappers curl/jq sont retirés, et la fenêtre « after » ne fait aucun curl : la version optimisée est bien celle qui tournait.
Correctif v5.9.1. Après la mesure, owl-check a révélé deux régressions de v5.8 : les affectations WANT… étaient collées par le compilateur OWL (erreur de syntaxe dans games/seasonAll), et le cache games écrivait .ok sur une réponse ESPN invalide. v5.9.1 ajoute les points-virgules, valide la réponse avant cache, met WANTLG dans SIG, refetch les caches vides et fallback favLg. Tests : make test.

Méthode et limites

  • Comptage exact : wrappers dans le shell invité, chaque appel curl/jq est journalisé avec son URL et son horodatage.
  • Fenêtres : 90 s de démarrage (burst) puis 120 s de régime stable, par version. Le téléphone est resté sur l'accueil, branché, avec stay_on_while_plugged_in=15.
  • Réseau : /proc/net/dev est refusé au shell invité (Permission denied) ; les octets n'ont pas pu être mesurés depuis le guest. Les compteurs d'appels sont exacts.
  • Durée : 2 min de régime stable suffisent pour le polling liveM (1 min), pas pour les sources à 6 h/12 h/24 h.
  • Variabilité : le burst initial dépend du nombre de ligues des équipes suivies.
